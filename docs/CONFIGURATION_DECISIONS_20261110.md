Siete agentes, todos sin run activo, sin cola pendiente, sin herramientas de aplicación conectadas ni MCP asociados y sin schedules. Tres lab usan Gemma y cuatro QA/supervisor Sonnet. Revisiones remotas comprensión/redactor/guardián: 1/4/1; no se sincronizaron prompts. Los nombres «free» no acreditan gratuidad.

`get_agent` ofrece también fuentes de archivos del volumen remoto y builtin decide (supervisor incluye ask_user); esos builtins no equivalen a acceso al checkout Windows, a la cola existente ni a PostgreSQL local. La superficie excede una aplicación sin herramientas. SpendLimit/runLimits de los agentes inspeccionados son null; no hay un permiso o presupuesto operativo demostrado para el objetivo actual. Los resultados/historiales devueltos incidentalmente por la API no se exportan al repositorio.

Capacidad concreta futura: ejecutar comprensión/redacción/guardián F3 sin que Codex haga cada llamada. Pero el gateway **ya implementa** `/v1/runs` stateless, esquemas, endpoint permitido, retención corta, autorización de evaluación y cota de coste. Duplicarlo o usar agentes conversacionales durables añadiría estado y riesgo de mezclar consultas. No aporta una puerta F1 nueva y no sustituye el disparador Windows ni alcanza su loopback.

Coste acreditado por documentación oficial consultada en lectura: runtime $0.01/h de agente activo, almacenamiento $0.10/GB-mes y tokens según proveedor/catálogo (OpenRouter añade factor 1.055), además de cargos por herramientas aplicables. El modelo no es el coste completo. No se comprobó el saldo, tier o tarifa efectiva del tenant; la respuesta extensa de list_models no permitió certificar de forma íntegra el catálogo. No hay autorización de gasto/inferencia en esta orden. Fuentes: [pricing](https://run.camelai.com/docs/pricing.md), [tools](https://run.camelai.com/docs/guides/tools.md), [límites](https://run.camelai.com/docs/reference/limits.md), leídas mediante read_docs oficial, sin navegador.

Antes de aprovecharlo: caso sintético y corpus congelado, presupuesto total aprobado y límites de run/retención, herramienta de aplicación sin acceso general al host, autorización aislada y verificación determinista de salida con requestId/uso/error auditados. El usuario/proveedor no decide permisos ni envío. Para datos reales se necesitan las puertas de privacidad, consentimiento y revisión humana existentes. No se crea otro adaptador ni se convierten estas dependencias en requisito de F1.
